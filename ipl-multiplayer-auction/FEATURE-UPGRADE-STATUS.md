# IPL Auction Feature Upgrade — implementation notes

This is an in-progress enhancement package based on the supplied multi-theme IPL auction project. It is not a production-certified release and should be reviewed against the live repository before deployment.

## Added in this update

### Auction management
- Host can defer the current player and defer the current set.
- Host can undo a set deferral through the socket action.
- Host can permanently skip the current set; remaining players in that set are marked unsold.
- Host can reorder sets using up/down controls on upcoming sets. The server validates the submitted set order.
- Host can start an unsold round after the auction ends, when unsold players remain.
- Deferred set keys are displayed in the host controls.

### Results and exports
- Export purchased players to CSV, including team, player, role, nationality, and purchase price.
- Export a team results CSV with squad size, overseas count, spend, remaining purse, and squad-shape score.
- Export unsold players to CSV.
- Export the loaded bid/event history to CSV.
- Results header controls wrap on smaller screens.

### Player watchlist
- Add/remove players from a personal watchlist from the sets view.
- Watchlist is stored in local browser storage and can be filtered as a separate view.

### Existing features retained
- Existing multi-theme picker, auction modes, room flow, and current player/stat UI are retained.

## Upgrade v3 continued — requested multiplayer, Playing XI, and auction experience features

### Multiplayer recovery and spectators
- Shows a live/reconnecting indicator in the auction workspace.
- On every successful Socket.IO connection/reconnection, rejoins the room and re-fetches durable room state, bids, squads, saved XI, and chat.
- The server avoids marking a participant offline if another socket for the same participant has already rejoined.
- Participants without a selected franchise can spectate; bidding remains disabled until they select a franchise.

### Playing XI
- Adds move-up/move-down controls to set batting order for selected players.
- Saves the XI in the displayed order through the existing API.
- Adds a clipboard export with numbered batting order and the plane emoji for overseas players.
- Existing server validation still limits the XI to 11 players and at most eight overseas players.

### Auction experience
- Adds QR invitation display in the lobby. The QR image is generated by an external QR service using the room invite link; the link is sent to that service to render the code.
- Adds six validated, room-wide live reactions.
- Adds an auction replay timeline from recorded bids and stored sold/unsold system events, plus an event-log CSV export. This is a timeline, not a frame-by-frame simulation of every UI state.
- Sold/unsold settlement writes a system event to the room chat history so those outcomes remain available after reload.

### Remaining limitations
- Shareable squad posters and full end-to-end browser validation are not included in this pass.
- Client production build still needs to be run in an environment where dependencies can install successfully.

## Deployment guidance

1. Back up the current repository and database.
2. Review the diff and merge into a local clone rather than uploading the ZIP over production blindly.
3. Run `npm ci && npm run build` in `client` and install server dependencies, then run the server tests.
4. Deploy the frontend and backend together for new socket actions to work.
5. Validate room creation/joining, set reorder, deferrals, skip-set, unsold round, CSV downloads, and watchlist in a test room before production use.


## Upgrade v3 — server-enforced overseas cap

- Enforced a maximum of eight overseas players per franchise during bidding, with a second validation at sale settlement.
- Added overseas-player counting to the transactional team totals query.
- Added matching client-side bid-button feedback and a clear `overseas_limit` message. The server is authoritative, so a modified client cannot bypass the rule.
- Added a regression test for the overseas cap rule.

Verification status: JavaScript syntax checks are run for the edited server modules. Full backend tests and frontend production build still require dependencies to install successfully and a configured database for integration testing.


## Upgrade v3 continued — multiplayer reliability

- Added bid-request idempotency: if a client retries an already accepted bid with the same request ID after a lost acknowledgement, the server returns the original bid rather than attempting a second bid. The room-state cache is bounded to the most recent 100 requests.
- Added server-side validation that a saved Playing XI contains no more than eight overseas players, including legacy squads that may predate the squad purchase limit.
